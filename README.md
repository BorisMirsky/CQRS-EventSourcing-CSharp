# Event Sourcing + CQRS на C# (Bank Account)

Pet-project для демонстрации паттернов **Event Sourcing** и **CQRS** без использования готовых фреймворков.  
Реализована луковая архитектура (Domain -> Application -> DataAccess -> Web), работа с SQLite через ADO.NET, Swagger UI.

Event Sourcing - архитектурный паттерн, отвечает за хранение изменений. Он работает с действиями, которые уже произошли.
Хранится не текущее состояние, а последовательность событий, которые к этому состоянию привели.


CQRS — архитектурный паттерн для разделения операций чтения и записи:

- Command side — принимает команды, меняет состояние через генерацию событий.

- Query side — подписывается на события и строит удобные проекции для чтения.


Event Sourcing и CQRS не обязательно использовать вместе, но в этом проекте они вместе.



## Технологии

- .NET 10
- C#
- SQLite (Microsoft.Data.Sqlite)
- ASP.NET Core Web API
- Swagger / Swashbuckle
- xUnit, Moq, FluentAssertions (тесты)

## Цели проекта

- Понять, как работают Event Sourcing и CQRS «под капотом».
- Разделить команды (запись) и запросы (чтение).
- Реализовать event store, read model, проекции и снимки (snapshots).
- Показать возможность восстановления состояния на любую дату.


## Ключевые понятия

- **Агрегат** (`BankAccount`) — корневая сущность, гарантирующая бизнес-правила. Все изменения порождают события.
- **Событие** — неизменяемый факт (AccountOpened, MoneyDeposited, MoneyWithdrawn, AccountFrozen, AccountUnfrozen).
- **Event Store** — таблица `event_store`, где события хранятся в виде JSON (append-only).
- **Read model** — денормализованные таблицы (`account_balances`, `transaction_history`) для быстрых запросов.
- **Проекция** — код, обновляющий read model после сохранения событий.
- **Снимок (snapshot)** — сохранённое состояние агрегата для ускорения загрузки длинной истории.

## Как запустить

1. Клонируйте репозиторий.
2. Убедитесь, что установлен .NET 10 SDK.
3. Перейдите в папку `EventSourcingSolution`.
4. Восстановите пакеты ```dotnet restore```
5. Соберите решение ```dotnet build```
6. Запустите Web-проект ```f5```
7. Откройте [Swagger](http://localhost:5108/swagger/index.html)

## API эндпоинты

### Команды (запись)

| Метод | Эндпоинт | Тело запроса (пример) | Описание |
|-------|----------|----------------------|----------|
| POST | `/api/Account/open` | `{ "ownerName": "John Doe", "currency": "USD" }` | Открыть новый счёт |
| POST | `/api/Account/{id}/deposit` | `{ "amount": 100, "currency": "USD", "description": "Salary" }` | Пополнить счёт |
| POST | `/api/Account/{id}/withdraw` | `{ "amount": 50, "currency": "USD", "description": "Cash" }` | Снять средства (проверка баланса) |
| POST | `/api/Account/{id}/freeze` | `{ "reason": "Suspicious activity" }` | Заморозить счёт |
| POST | `/api/Account/{id}/unfreeze` | `{ "reason": "Investigation cleared" }` | Разморозить счёт |

### Запросы (чтение)
| Метод | Эндпоинт | Параметры | Описание |
|-------|----------|-----------|----------|
| GET | `/api/Account/{id}/balance` | `id` (GUID) | Текущий баланс и статус заморозки |
| GET | `/api/Account/{id}/history` | `id` (GUID) | История всех транзакций |
| GET | `/api/Account/{id}/balance-at-date` | `id` (GUID), `date` (YYYY-MM-DD) | Баланс на указанную дату (переигрывание событий) |

## Как тестировать

### Ручное тестирование через Swagger
1. Открыть счёт → получить accountId (можно посмотреть в БД или временно добавить возврат).
2. Пополнить, снять, заморозить — проверять ошибки (недостаточно средств, заморожен).
3. Вызвать GET-запросы для проверки read-модели.
4. Запросить баланс на прошлую дату — убедиться, что события переигрываются.

### Модульные тесты 
В проекте реализованы тесты для:

- Домена (агрегат, правила)
- Сериализации/десериализации событий
- Загрузки истории (LoadFromHistory)
- Снапшотов (интеграционные тесты пропущены, но реализованы)

Запустить все тесты из корня проекта: ```dotnet tests```

## Проверка снимков (snapshots)
По умолчанию снимок создаётся каждые 50 событий. Для демонстрации можно временно уменьшить порог в SqliteEventStore.SnapshotThreshold = 5. После выполнения 5 событий появится запись в таблице aggregate_snapshots.

## Структура проекта (слои)
- Domain — агрегаты, события, value objects, интерфейсы (абстракции).
- Application — команды, запросы, хендлеры, порты (IEventStore, IReadModelRepository).
- DataAccess — реализация event store, read model, снимков (SQLite, ADO.NET).
- Web — контроллеры, DTO, Swagger, DI.
